# Implementation Plan: P22-NN swarm (parallel DeepSeek lanes, end to end)

Version 2 of the P22-NN execution plan, 2026-09-24. Science, assumptions (A1–A16),
design, evidence rules and IF/ELSE branches are unchanged and live in:
`tasks/nn/plan.md` (§0–§7), `tasks/nn/decision_tree.md`, `tasks/nn/todo.md` (task specs).
This file adds only the **parallel execution layer**. The orchestrator is `gnhf/swarm.py`;
stage and lane definitions are `tasks/nn/swarm/lanes.json` (single source of truth).

## Overview

Several GNHF/DeepSeek agents run at once, each in its own git worktree under
`P22/.worktrees/<lane>` on branch `gnhf/p22-nn-<lane>`. A stage runs its lanes in
parallel; when all lanes finish, the orchestrator merges each lane branch into the
integration branch `gnhf/p22-nn-cellstate` (the main `P22` checkout), runs the focused
test suite, checks the stage gate, syncs the `todo.md` status table, and starts the next
stage. No human step is needed between stages.

## Architecture decisions

- **One worktree per agent.** GNHF rolls back a failed iteration with
  `git reset --hard HEAD && git clean -fd`; two agents in one checkout would erase each
  other's work. Worktrees live inside `P22/.worktrees/` (excluded from git status) so all
  code stays under `/Users/anuragdani/Github/niw-eb1a/P22`.
- **Status files, not a shared table.** Each task's state is one line in
  `tasks/nn/status/<ID>`. Different lanes never edit the same file, so merges do not
  conflict. `todo.md`'s table is regenerated by the orchestrator after each merge.
- **File ownership per lane** (`owns` in lanes.json). A lane edits only its owned files,
  its status files and its log `tasks/nn/lanes/<lane>.md`. Shared inputs are read-only.
- **Shared heavy outputs.** `reports/generated/nn_20260923` in every worktree is a symlink
  to the main checkout's directory, so S3 lanes can read S2 models and predictions.
- **CPU budget.** 16 cores. Each lane gets a fixed `workers` count; lanes of one stage sum
  to ≤ 16 (1 torch thread per worker process).
- **Stage barriers** keep dependencies simple: a lane only ever needs results merged at
  an earlier stage.
- **Failure policy.** Lane stalls (3 attempts without a new commit) or attempt exhaustion →
  its unresolved tasks become `BLOCKED:lane_<reason>`; downstream tasks apply their
  decision-tree fallbacks. Provider key/credit errors → the orchestrator stops the whole
  swarm (exit 4) without marking tasks BLOCKED; rerunning resumes.

## Lane rules (every agent)

1. Work only in your worktree and branch. Never merge, rebase, switch branches, push or
   edit another worktree. The orchestrator merges.
2. Edit only your lane's owned files, `tasks/nn/status/<your IDs>` and
   `tasks/nn/lanes/<lane>.md`. Never edit `tasks/nn/todo.md`, `tasks/nn/plan.md`,
   `tasks/nn/decision_tree.md`, `tasks/nn/swarm/*`, `gnhf/*`, `paper/refs_frozen.bib`.
3. Where `plan.md`/`decision_tree.md` say "status table" or "Run log", read
   "`tasks/nn/status/<ID>`" and "`tasks/nn/lanes/<lane>.md`".
4. Status file format: exactly one line: `TODO` | `RUNNING:<pid>:<log>` |
   `DONE:<evidence>` | `BLOCKED:<reason>:<evidence>` | `NOT_NEEDED:<evidence>`.
5. Use at most your lane's `workers` processes. Heavy outputs go under
   `reports/generated/nn_20260923/<task>/` (shared symlink).
6. One numbered step per iteration; focused tests + ruff on touched files; GNHF commits.
7. All plan §7 honesty, leakage and no-new-experiment rules apply unchanged.

## Verification (orchestrator, after every stage)

1. `git merge --no-ff` each lane branch into `gnhf/p22-nn-cellstate`. Conflict → a
   bounded GNHF fixer run (≤ 8 iterations) in the main checkout resolves it; if the
   branch is still unmerged → swarm exits 5.
2. `PY -m pytest -q -x tests/test_nn_*.py` (plus `tests/test_paper_tools.py` when it
   exists). Failure → bounded fixer run "make tests pass without changing results";
   still failing → logged in the gate record, swarm continues (downstream fallbacks).
3. Gate files present → `PASS`; else `FAIL` logged; the swarm continues because every
   downstream task has a fallback.
4. Regenerate the `todo.md` status table from `tasks/nn/status/*`; commit.
5. Write `reports/generated/nn_swarm/<stamp>/gates.json` and refresh `status.json`.

## Risks and mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| OpenRouter key limit hit by 4–5 concurrent agents | High | Detected from attempt logs → swarm exits 4 cleanly; rerun resumes from status files |
| Merge conflict on a shared file | Med | File ownership; status files per task; fixer run; exit 5 if unresolved |
| CPU oversubscription | Med | Per-lane worker caps sum ≤ 16; torch threads 1 |
| Disk (14 GiB free; 10 GiB reserve) | Med | Worktrees ≈ 20 MB each; heavy outputs shared once; G6 rules |
| Lane agent edits a non-owned file | Med | Lane rules; merge conflict path; tests after merge |
| Stale single-agent batch still running | High | Orchestrator takeover: waits for the batch's next iteration end, then stops it and preserves leftovers as a WIP commit |
| GNHF "no final answer" / step-limit failures | Low | Attempt loop relaunches; stall counter marks BLOCKED after 3 empty attempts |
